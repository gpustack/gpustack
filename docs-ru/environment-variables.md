# Переменные среды { #environment-variables }

GPUStack поддерживает различные переменные среды для настройки.

Большинство параметров командной строки также можно задать с помощью переменных среды с префиксом `GPUSTACK_` и в верхнем регистре (например, `--data-dir` можно установить с помощью `GPUSTACK_DATA_DIR`).

Полный список параметров командной строки, которые можно установить в качестве переменных среды, см. в [Справочнике по CLI](cli-reference/start.md#available-environment-variables). Здесь это обсуждаться не будет.

### Приоритетный порядок { #priority-order }

Значения конфигурации применяются в следующем порядке приоритета (от самого высокого к самому низкому):

1. Аргументы командной строки
2. Переменные среды
3. Файл конфигурации.
4. Значения по умолчанию

Это означает, что аргументы командной строки всегда будут переопределять переменные среды, а переменные среды будут переопределять значения в файле конфигурации.

## Переменные среды ядра GPUStack { #gpustack-core-environment-variables }

Эти переменные среды обычно используются для интеграции сторонних сервисов.

Столбец **Applies to** указывает, где должна быть установлена переменная среды:

- **Сервер** — применяется к серверу GPUStack.
- **Worker** — применяется к работникам GPUStack.
- **Модель** — применяется к конфигурациям развертывания модели.

### Конфигурация шлюза { #gateway-configuration }

| Переменная | Описание | По умолчанию | Применяется к |
| -------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------- | ---------- |
| `GPUSTACK_GATEWAY_PORT_CHECK_INTERVAL`             | Интервал в секундах от GPUStack Сервер проверяет порт прослушивания встроенного шлюза. | `2`       | Сервер |
| `GPUSTACK_GATEWAY_PORT_CHECK_RETRY_COUNT`          | Число повторных попыток GPUStack Сервер проверяет порт прослушивания встроенного шлюза. | `300`     | Сервер |
| `GPUSTACK_GATEWAY_AUTH_RECONCILE_INTERVAL_SECONDS` | Как часто сервер заново считывает из базы данных набор ключей API, которые шлюз проверяет локально. Удаление в обход ORM не создаёт события, поэтому на публичном маршруте это максимальное время, в течение которого удалённый таким образом ключ может продолжать работать. | `30`      | Сервер |
| `GPUSTACK_GATEWAY_AUTH_ALLOW_CUSTOM_KEYS`          | Может ли пользовательский ключ API (тот, секрет которого предоставил пользователь) аутентифицироваться на шлюзе. Выключено, он продолжает работать, но запрашивает сервер при каждом запросе. Включенный ключ публикуется в конфигурации шлюза, индексируемый несоленым быстрым хешем самого секрета — идентичным во всех развертываниях, поэтому слабый секрет попадает в заранее вычисленную таблицу. `custom` не налагает никаких требований к энтропии, поэтому отключите этот параметр, когда пользователи выбирают свои собственные ключи — он перечитывается при каждом согласовании, поэтому он удаляет пользовательские ключи, опубликованные, пока он был включен, а не только новые. | `true`    | Сервер |
| `GPUSTACK_GATEWAY_AUTH_MAX_CR_BYTES`               | Бюджет в байтах для ключевых таблиц и правил общедоступного маршрута, который сервер записывает в плагин аутентификации шлюза. Размер не превышает ограничения объекта etcd ~1,5 МБ; ключи, проходящие мимо него, аутентифицируются через сервер при каждом запросе. | `1100000` | Сервер |
| `GPUSTACK_GATEWAY_TLS_MIN_PROTOCOL_VERSION`        | Минимальная версия протокола TLS, принимаемая HTTPS-слушателями шлюза. Допустимы `TLSv1.0`, `TLSv1.1`, `TLSv1.2`, `TLSv1.3`; другие значения отклоняются при запуске. Пустое значение оставляет настройки Higress по умолчанию, допускающие TLS 1.0 и 1.1. Игнорируется в режиме `incluster` — см. ниже. | (пусто) | Сервер |
| `GPUSTACK_GATEWAY_TLS_MAX_PROTOCOL_VERSION`        | Самая высокая версия, которую принимают слушатели. Те же ценности и та же область применения; нужен редко. | (пусто) | Сервер |

Конфигурация версии протокола TLS записывается на вход с именем `GPUSTACK_GATEWAY_MIRROR_INGRESS_NAME`, и каждый входной GPUStack, создаваемый для маршрута LLM, копирует из него границы. В режиме `incluster` вход принадлежит чарту Helm, поэтому вместо этого установите там `server.ingress.tls.minProtocolVersion` / `maxProtocolVersion` — переменные игнорируются, и установка одной из них регистрирует предупреждение. Изменение применяется к этому входу немедленно, а также к существующим маршрутам LLM при их следующем согласовании; перезапустите сервер для немедленного распространения.

Настройки, которые заканчиваются **внутри** конфигурации плагина шлюза, задаются в файле конфигурации под `gateway_plugin`, а не здесь, так что каждый механизм имеет одну историю эффективного времени — значение там вступает в силу при следующем согласовании, переменная здесь — при перезапуске. Два ниже перемещены туда и устарели. Они по-прежнему учитываются, поскольку файл конфигурации по умолчанию может переопределять их, поэтому обновление не приводит к автоматическому возврату развертывания, в котором они были установлены; установка любого из них регистрирует предупреждение.

| Устаревшая переменная. | Описание | Заменено на | По умолчанию | Применяется к |
| ----------------------------------------------------- | -------------------------------------------------------- | ---------------------------------------------------------- | ------------------------------------ | ---------- |
| `GPUSTACK_HIGRESS_EXT_AUTH_TIMEOUT_MS`                | Тайм-аут вызова аутентификации шлюза в миллисекундах. | `gateway_plugin.gpustack-ext-auth.config.authz.timeout`    | `30000`                              | Сервер |
| `GPUSTACK_GATEWAY_AI_STATISTICS_PLUGIN_CONTENT_TYPES` | Типы контента, разделенные запятыми, с учетом использования токенов. | `gateway_plugin.ai-statistics.config.enable_content_types` | `application/json,text/event-stream` | Сервер |

!!! note "`GPUSTACK_TIMEZONE` область и летнее время"

    Этот часовой пояс управляет каждым представлением использования: ежедневным накоплением токенов `model_usages`, сегментами времени графического процессора/хранилища, а также отображаемым временем последней активности и событиями ресурсов. Для зоны, в которой наблюдается **DST**, это имеет два последствия, о которых стоит знать:

    - При переходе на летнее время отображаемое время события может приходиться на другой календарный день, чем тот период, в котором оно отсчитывается.
    - Повторный запуск того же исторического запроса после переключения на летнее время может привести к повторному группированию старых строк на час, поэтому результат со временем будет меняться.

    Зоны без летнего времени (UTC, `Asia/Shanghai`, …) указаны точно и не подвержены влиянию.

#### Планирование многоролевой группы { #multi-role-group-scheduling }

Эти веса и окна применяются к развертываниям, в которых объявляются роли — дезагрегированная группа предварительного заполнения-декодирования и ее маршрутизатор. Они не влияют на простое развертывание с одной ролью. Каждая оценка ниже представляет собой максимальный вклад в цепочку оценок планировщика; установка значения `0` полностью устраняет это соображение.

| Переменная | Описание | По умолчанию | Применяется к |
| ---------------------------------------------------- | --------------------------------------------------------------------------- | ------- | ---------- |
| `GPUSTACK_SCHEDULER_TOPOLOGY_PROXIMITY_MAX_SCORE`    | Максимальный балл за ступень топологии, которую кандидат-работник разделяет с уже размещенными членами группы, при масштабировании роли или размещении маршрутизатора. Устанавливается выше 100-балльного разброса счетчика размещения, чтобы свободная мощность не могла перевесить целую ступень заявленной топологии. `0` размещает более поздних участников по ресурсу, подходящему отдельно. | `150`   | Сервер |
| `GPUSTACK_SCHEDULER_PAIRING_AFFINITY_MAX_SCORE`      | Максимальный балл за каждого участника противоположной роли, уже находящегося на кандидате-воркере, при масштабировании одной роли разделённой группы — благодаря этому передача KV остаётся на одном хосте. Это **нижняя граница**, а не фактически используемый вес: планировщик берёт максимум из этого значения и суммы верхних границ остальных оценщиков в цепочке плюс один, чтобы правило «побеждает большинство участников противоположной роли, а ёмкость разрешает ничью» действовало при любом наборе оценщиков. `0` отключает этот критерий и никогда не повышается до нижней границы. | `200`   | Сервер |
| `GPUSTACK_SCHEDULER_SCALE_DOWN_PAIRING_MAX_SCORE`    | Максимальный вклад участников противоположной роли на том же воркере в балл сохранения участника при уменьшении одной роли группы. Определяет удаляемого участника в обычном случае, когда все лишние участники исправны, а баллы состояния и выгрузки равны. Держите его **ниже 50** — разницы между «запускается» и «работает» у оценщика состояния. При значении 50 или выше запускающийся участник с соседями обгонит исправного участника без соседей, и планировщик перестанет в первую очередь удалять уже неисправного участника. `0` выбирает удаляемого участника только по состоянию и размещению. | `20`    | Сервер |
| `GPUSTACK_SCHEDULER_DRAIN_WINDOW_SECONDS`            | Как долго член группы с уменьшенным масштабом продолжает работать после выхода из реестра маршрутизатора. Это не период отсрочки процесса: это время, в течение которого необходимо завершить декодирование, все еще извлекающее кэш KV из этого элемента, и движок не имеет возможности дождаться этого момента самостоятельно. `0` удаляется немедленно, что и делает развертывание без ролей. | `60`    | Сервер |
| `GPUSTACK_SCHEDULER_GATHER_BLOCKED_DWELL_SECONDS`    | Как долго член группы `MustGather` может сидеть без места до отчета о развертывании `gather_blocked_scale_out`. Ничто не истекает при его прохождении — оно только отделяет «планировщик еще не запущен» от «планировщик запущен, и внутри домена сбора некуда это поместить». При каждом увеличении масштаба расходуется первый из них, поэтому без задержки маркер появится на всех из них. `0` сообщает об отказе, как только появится неразмещенный участник. | `120`   | Сервер |

#### Пример использования { #usage-example }

При развертывании модели перейдите к **Дополнительные параметры > Переменные среды** и добавьте:

```bash
# Install additional packages before model serving starts
PYPI_PACKAGES_INSTALL=torch-audio==2.0.0 transformers==4.30.0

# Disable the serving command script entirely
GPUSTACK_MODEL_SERVING_COMMAND_SCRIPT_DISABLED=1
```

Скрипт обслуживающей команды автоматически обрабатывает:

- Установка дополнительных пакетов PyPI, указанных в `PYPI_PACKAGES_INSTALL`.
- Поддержка `uv pip` и `pip` для установки пакета.
- Обработка пользовательских индексов PyPI через `PIP_INDEX_URL` и `PIP_EXTRA_INDEX_URL`
