# Запуск распределенной vLLM с помощью серверной части MultiProcessing. { #running-distributed-vllm-with-the-multiprocessing-backend }

Если одному рабочему процессу не хватает памяти графического процессора или вычислительных ресурсов для размещения модели, vLLM может разделить один экземпляр модели на несколько рабочих процессов для совместного вывода. GPUStack организует эти межузловые процессы как **одиночный** экземпляр модели и предоставляет только одну конечную точку, совместимую с OpenAI. vLLM предлагает два пути выполнения через параметр `--distributed-executor-backend`: `ray` и `mp` (MultiProcessing). В этом руководстве показано, как использовать серверную часть **MP** для выполнения распределенного вывода между несколькими рабочими процессами с комбинацией тензорного параллелизма (TP) и параллелизма данных (DP).

В этом руководстве вы узнаете, как включить распределенный логический вывод между работниками в GPUStack, явно выбрать серверную часть MP и объединить тензорный параллелизм с параллелизмом данных для развертывания одного экземпляра модели на двух узлах.

!!! note

    - Серверная часть MP вступает в силу, когда вы явно устанавливаете `--distributed-executor-backend=mp` в `Backend Parameters` или когда вы используете собственный образ (версия внутренней части с суффиксом `-custom`) с vLLM ≥ `0.18.0`. Начиная с `0.18.0`, vLLM больше не зависит от Ray по умолчанию, поэтому GPUStack автоматически возвращается к `mp`, чтобы избежать сбоев при запуске.
    - Концептуальные различия между путями Ray и MP, безголовым последователем и топологиями `dp_only` / `mp_only` / `nested` см. в разделе `Distributed Inference Across Workers` в [Встроенные механизмы вывода](../user-guide/built-in-inference-backends.md).
    - Эта функция в настоящее время является экспериментальной.

## Предварительные условия { #prerequisites }

Прежде чем начать, убедитесь, что у вас есть следующее:

- GPUStack установлен и работает.
- Не менее **2 узлов Linux**, каждый из которых имеет **одинаковое количество и одну и ту же модель** графических процессоров. В этом руководстве в качестве примера используется **2 узла × 8 графических процессоров** (всего 16 графических процессоров), применимых к ускорителям различных поставщиков, таких как NVIDIA, AMD и Ascend.
- Для повышения производительности рекомендуется использовать высокоскоростное соединение между узлами (например, NVLink или InfiniBand).
- Файлы модели должны быть доступны по **одному и тому же пути на каждом участвующем узле**. Используйте общую файловую систему или заранее загрузите файлы модели по одному и тому же пути на каждом узле.
- Выбранная модель подходит для компоновки `tensor-parallel-size=8`, `data-parallel-size=2` (т. е. каждая реплика с параллельными данными занимает один полный узел с 8 графическими процессорами).

!!! note

    В этом руководстве предполагается, что каждая реплика с параллельными данными (`tensor-parallel-size=8`) полностью занимает один узел с 8 графическими процессорами. Настройте `--tensor-parallel-size` и `--data-parallel-size` в соответствии с вашей моделью и оборудованием.

## Шаг 1. Добавьте рабочие процессы GPUStack. { #step-1-add-gpustack-workers }

После [Установка](../installation/installation.md) запустите команду соединения на каждом узле, чтобы добавить их в один и тот же кластер GPUStack.

После их присоединения подтвердите на странице `Workers` пользовательского интерфейса GPUStack, что оба узла находятся в состоянии готовности и что их графические процессоры указаны в списке.

![Снимок экрана: рабочая страница, на которой показаны два готовых узла](../assets/tutorials/running-distributed-vllm-with-multiprocessing/1-workers-ready.png)

## Шаг 2. Развертывание модели с помощью серверной части MP. { #step-2-deploy-the-model-with-the-mp-backend }

1. Перейдите на страницу `Deployments`.
2. Нажмите `Deploy Model`, выберите источник модели (например, `Local Path`) и введите путь модели, одинаковый для всех узлов.
3. Убедитесь, что для `Backend` установлено значение `vLLM`.
4. В дополнительных настройках установите флажок `Allow Distributed Inference Across Workers`, чтобы включить распределенный вывод между работниками.
5. Добавьте следующие параметры в `Backend Parameters`:

    ```bash
    --distributed-executor-backend=mp
    --tensor-parallel-size=8
    --data-parallel-size=2
    --enable-expert-parallel
    ```

6. После прохождения проверки совместимости нажмите `Save` для развертывания.


!!! tip "Разверните весь распределенный экземпляр как одно развертывание."

    Мы рекомендуем развертывать распределенный экземпляр между узлами как **одиночное** развертывание. Когда вы создаете только одно развертывание, как описано выше, GPUStack:

    - выберите графические процессоры для обоих рабочих процессов (16 в этом примере) и автоматически получите значение `--data-parallel-size-local` для каждого узла, поэтому вам **не нужно устанавливать** `--data-parallel-size-local` вручную;
    - внедрить параметры многоузловой топологии `--nnodes`, `--node-rank`, `--master-addr` и `--master-port`;
    - автоматически добавляет `--headless` к экземплярам последователей, чтобы они участвовали только в распределенных вычислениях и не запускали конечную точку API. Ожидается появление `--headless` в журналах подписчиков.

!!! note "Когда автоматическое планирование не может быть выполнено"

    Если автоматическое планирование не может выделить ресурсы из-за невыполнения условия (например, память графического процессора не удовлетворяет `gpu_memory_utilization`), переключите `Scheduling Mode` на `Manual` или `Specify GPU`, а затем используйте `GPU Selector`, чтобы выбрать 8 графических процессоров на каждом из двух рабочих процессов (всего 16). См. [Встроенные механизмы вывода](../user-guide/built-in-inference-backends.md) для получения полных условий автоматического планирования.


!!! note "При разделении на несколько развертываний вручную: используйте `GPUSTACK_SKIP_GPU_COUNT_CHECK`, чтобы пропустить проверку количества графических процессоров."

    В некоторых сценариях вам может потребоваться создать одно развертывание для каждого узла (например, для самостоятельного управления внешним балансировщиком нагрузки), выбрав графические процессоры вручную и установив `--data-parallel-size-local 1` вручную. В этом случае каждое развертывание выбирает только 8 графических процессоров, а `tensor-parallel-size × data-parallel-size = 16`, поэтому GPUStack сообщает об ошибке, поскольку количество графических процессоров не соответствует размеру мира: `the selected gpu count (8) does not match the world size (16)`.

    Если это ваш предполагаемый макет, установите `GPUSTACK_SKIP_GPU_COUNT_CHECK=1` в `Environment Variables` каждого развертывания, чтобы пропустить проверку и сохранить выбранное вручную количество графических процессоров. Этот переключатель **действует только тогда, когда графические процессоры выбраны вручную** ​​(`Scheduling Mode` — это `Manual` или `Specify GPU`) и не влияет на автоматическое планирование.

## Шаг 3. Мониторинг развертывания { #step-3-monitor-deployment }

Отслеживайте статус развертывания на странице `Deployments`. Наведите указатель мыши на `Distributed Across Workers`, чтобы просмотреть использование графического процессора экземпляра для каждого рабочего процесса. Нажмите `View Logs`, чтобы просмотреть журналы в реальном времени:

- Экземпляр **leader** загружает модель и предоставляет конечную точку, совместимую с OpenAI;
- В журналах экземпляра **follower** указано `--headless`, что означает, что он участвует только в распределенных вычислениях и не занимает порт API. Это ожидаемо.

Загрузка модели может занять несколько минут.

![Снимок экрана: детали развертывания, показывающие распределение по работникам](../assets/tutorials/running-distributed-vllm-with-multiprocessing/3-distributed-across-workers.png)

## Шаг 4. Проверка через Песочницу. { #step-4-verify-via-the-playground }

После запуска развертывания проверьте его непосредственно в Песочнице GPUStack. Все внешние запросы поступают через лидера, который отправляет их последователям, поэтому их использование идентично развертыванию с одним работником:

1. Перейдите к `Playground` > `Chat`.
2. Если развернута только одна модель, она выбирается по умолчанию; в противном случае выберите свою модель в раскрывающемся меню в правом верхнем углу.
3. Введите подсказку и взаимодействуйте с моделью.

![Скриншот: Общение с распределенной моделью в Песочнице](../assets/tutorials/running-distributed-vllm-with-multiprocessing/4-playground-chat.png)

Теперь вы успешно развернули и запустили распределенный вывод на нескольких узлах в кластере GPUStack, используя серверную часть MP vLLM.

Если вам нужна дополнительная помощь, обращайтесь в сообщество GPUStack или в службу поддержки.
