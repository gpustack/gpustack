# NVIDIA H100 GPU üzerinde GLM-4.x işlem hacmi optimizasyonu { #optimizing-glm-4x-throughput-on-nvidia-h100-gpus }

## Sonuç { #conclusion }

H100 GPU üzerinde GLM-4.x (4.5, 4.6 ve 4.7) işlem hacmini optimize etmek için önerilen yapılandırma:

???+ tip "Model sunum komutu"
    ```bash
    python3 -m sglang.launch_server --model zai-org/GLM-4.6-FP8 --tp-size 8 --ep-size 8 --tool-call-parser glm --reasoning-parser glm45
    ```

!!! note
    1. Benchmark testlerimiz olası tüm optimizasyon birleşimlerini kapsamaz. Örneğin, varsayılan yapılandırmasında en iyi performansı gösteren çıkarım motorunu sonraki ayarlamalar için başlangıç noktası olarak seçeriz. Bu eleme yaklaşımı yerel bir optimum verir; bu, genel optimum olmayabilir.
    2. En büyük toplu iş boyutu, zamanlama yapılandırması, genişletilmiş KV önbelleği, CUDA graph gibi belirli kullanım senaryolarına bağlı başka optimizasyonlar da vardır. Bu belgedeki sonuçlar, daha hedefli optimizasyonlar için başlangıç noktası olabilir.
    3. Testler belirli donanım ve yazılım yapılandırmalarında yürütülmüştür. Çıkarım motorlarındaki gelişmeler sonuçları değiştirebilir.
    4. Nicemleme doğruluğu etkileyebilir; ancak FP8 nicemleme çoğu modelde %1'den az doğruluk kaybı sağlayabilir. Ayrıntılar için [değerlendirme sonuçlarına](https://github.com/Tencent/AngelSlim/blob/main/README_en.md#-benchmark) bakın. Bu nedenle yüksek işlem hacimli sunum senaryolarında FP8 nicemleme önemle önerilir.

Eksik noktalar veya yeni değişiklikleri yansıtacak güncellemeler varsa [bize bildirin](https://github.com/gpustack/gpustack/issues/new/choose).

## Optimizasyon hedefi { #optimization-objective }

Yüksek eş zamanlı isteklerde yüksek işlem hacmi sağlar.

## Deney kurulumu { #experimental-setup }

### Model { #model }

zai-org/GLM-4.6

### Donanım { #hardware }

Tek düğümde 8 × NVIDIA H100 SXM GPU.

### Motor sürümü { #engine-version }

- vLLM: v0.11.0
- SGLang: v0.5.3
- TensorRT-LLM: v1.0.0

### Benchmark veri kümesi { #benchmark-dataset }

1. ShareGPT
2. Farklı dizi uzunluklarına sahip rastgele veri kümesi:
    - Çok uzun istem: 32000 giriş token'ı, 100 çıkış token'ı
    - Uzun istem: 4000 giriş token'ı, 200 çıkış token'ı
    - Orta uzunlukta istem: 2000 giriş token'ı, 100 çıkış token'ı
    - Kısa istem: 128 giriş token'ı, 4 çıkış token'ı

### Benchmark betiği { #benchmark-script }

Model performansını ölçmek için **vLLM bench CLI** aracını kullanıyoruz. Benchmark şu komutla çalıştırılır:

```bash
# Prepare the ShareGPT dataset
wget https://huggingface.co/datasets/anon8231489123/ShareGPT_Vicuna_unfiltered/resolve/main/ShareGPT_V3_unfiltered_cleaned_split.json

# Benchmark on ShareGPT dataset
vllm bench serve --model zai-org/GLM-4.6 --backend openai-chat --endpoint /v1/chat/completions --dataset-name sharegpt --dataset-path ShareGPT_V3_unfiltered_cleaned_split.json --num-prompts 1000

# Benchmark on random dataset (fixed seed for reproducibility)
vllm bench serve --model zai-org/GLM-4.6 --backend openai-chat --endpoint /v1/chat/completions --dataset-name random --random-input-len 4000 --random-output-len 200 --num-prompts 500 --seed 42
```
