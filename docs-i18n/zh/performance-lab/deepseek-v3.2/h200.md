# NVIDIA H200 GPUs 上的 DeepSeek-V3.2 吞吐量优化 { #optimizing-deepseek-v32-throughput-on-nvidia-h200-gpus }

## 结论 { #conclusion }

![DeepSeek-V3.2 H200 吞吐量优化](../../assets/performance-lab/deepseek-v3.2-h200.png)
在配备 H200x8 的单节点上优化 DeepSeek-V3.2 吞吐量的推荐配置：

???+ tip "推理服务命令"
    ```bash
    python3 -m sglang.launch_server --model deepseek-ai/DeepSeek-V3.2 \
    --chat-template ./tool_chat_template_deepseekv32.jinja \
    --tp-size 8 --dp-size 8 --enable-dp-attention \
    --reasoning-parser deepseek-v3 \
    --tool-call-parser deepseekv32
    ```

[tool_chat_template_deepseekv32.jinja](https://github.com/sgl-project/sglang/blob/main/examples/chat_template/tool_chat_template_deepseekv32.jinja) 文件链接。

根据以下基准测试，建议使用上述配置优化 **DeepSeek-V3.2** 在 **8×H200** 上的吞吐量。

**并行策略**和**工具调用配置**带来的性能提升最大，因此纳入推荐命令。**调整上下文长度**可以进一步提高吞吐量，但效果高度依赖工作负载，应根据实际使用情况调优。
**注意力后端**优化虽然有效，但收益相对较小，且可能随数据集变化，因此未纳入默认推荐配置。

优化前后的基准测试结果对比：

| 基准测试用例 | 基准配置（未做任何优化的 vLLM） | 优化后 |
|---------------|--------------------------------------------|-----------|
| **ShareGPT** | Total TPS: 5713.95<br>Mean TPOT(ms): 275.03 | Total TPS: 8968.32 <span style="background-color:lightgreen;">(+56.95%)</span><br>Mean TPOT(ms): 203.05 |
| **短提示词** | Total TPS: 10071.49<br>Mean TPOT(ms): 781.80 | Total TPS: 18227.38 <span style="background-color:lightgreen;">(+80.98%)</span><br>Mean TPOT(ms): 776.55 |
| **中等长度提示词** | Total TPS: 10925.59<br>Mean TPOT(ms): 354.59 | Total TPS: 27712.54 <span style="background-color:lightgreen;">(+153.65%)</span><br>Mean TPOT(ms): 192.24 |
| **长提示词** | Total TPS: 9974.26<br>Mean TPOT(ms): 226.74 | Total TPS: 20545.67 <span style="background-color:lightgreen;">(+105.99%)</span><br>Mean TPOT(ms): 177.95 |
| **超长提示词** | Total TPS: 9709.27<br>Mean TPOT(ms): 472.52 | Total TPS: 20045.18 <span style="background-color:lightgreen;">(+106.45%)</span><br>Mean TPOT(ms): 246.26 |
| **生成密集型提示词** | Total TPS: 3112.52<br>Mean TPOT(ms): 45.72 | Total TPS: 3703.98 <span style="background-color:lightgreen;">(+19.0%)</span><br>Mean TPOT(ms): 39.45 |

!!! note
    1. 基准测试未覆盖所有可能的优化组合。例如，我们会选择默认配置下表现最好的推理引擎作为后续调优的起点。这种剪枝方式得到的是局部最优解，未必是全局最优解。
    2. 其他优化方法取决于具体使用场景，包括最大批大小、调度配置、扩展 KV cache、CUDA graph 等。本文结论可作为进一步针对性优化的起点。
    3. 测试基于特定的硬件和软件环境。推理引擎的改进可能带来新的结论。

如有遗漏或需要根据最新变化更新的内容，请[告诉我们](https://github.com/gpustack/gpustack/issues/new/choose)。


## 优化目标 { #optimization-objective }

在高并发请求场景下实现高吞吐量。

## 实验环境 { #experimental-setup }

### 模型 { #model }

deepseek-ai/DeepSeek-V3.2

### 硬件 { #hardware }

单节点配备 8 × NVIDIA H200 SXM GPU。

### 引擎版本 { #engine-version }

- vLLM: v0.13.0
- SGLang: v0.5.6.post2
- TensorRT-LLM: 1.2.0rc5

### 基准测试数据集 { #benchmark-dataset }

1. ShareGPT
2. 不同序列长度的随机数据集：
    - 超长提示词：32000 输入 tokens，100 输出 tokens
    - 长提示词：4000 输入 tokens，200 输出 tokens
    - 中等长度提示词：2000 输入 tokens，100 输出 tokens
    - 短提示词：128 输入 tokens，4 输出 tokens
    - 生成密集型提示词：1K 输入 tokens，2K 输出 tokens

### 基准测试脚本 { #benchmark-script }

使用 **vLLM bench CLI** 工具对模型性能进行基准测试。运行基准测试的命令如下：

```bash
# Prepare the ShareGPT dataset
wget https://huggingface.co/datasets/anon8231489123/ShareGPT_Vicuna_unfiltered/resolve/main/ShareGPT_V3_unfiltered_cleaned_split.json

# Benchmark on ShareGPT dataset
vllm bench serve --model deepseek-ai/DeepSeek-V3.2 --backend openai-chat --endpoint /v1/chat/completions --dataset-name sharegpt --dataset-path ShareGPT_V3_unfiltered_cleaned_split.json --num-prompts 1000

# Benchmark on random dataset (fixed seed for reproducibility)
vllm bench serve --model deepseek-ai/DeepSeek-V3.2 --backend openai-chat --endpoint /v1/chat/completions --dataset-name random --random-input-len 4000 --random-output-len 200 --num-prompts 500 --seed 42
```

#### 并行策略: DCP { #parallelism-dcp }

??? info "推理服务脚本"
    ```bash
    vllm serve deepseek-ai/DeepSeek-V3.2 -tp 8 --tokenizer-mode deepseek_v32 --reasoning-parser deepseek_v3 \
    -dcp 8
    ```

DeepSeek V3.2 依赖 FlashMLA 稀疏注意力后端，该后端目前在解码阶段不提供 softmax log-sum-exp（LSE）。由于解码上下文并行（DCP）需要 softmax LSE 才能正确执行跨 rank 聚合，FlashMLA 目前不支持 DCP，在 vLLM 中使用时会导致运行失败。vLLM 仓库中已讨论这一限制（参见 issue [#27544](https://github.com/vllm-project/vllm/issues/27544)）。
