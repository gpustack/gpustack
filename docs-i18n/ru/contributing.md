# Участие в GPUStack { #contributing-to-gpustack }

Спасибо, что нашли время внести свой вклад в GPUStack!

Пожалуйста, ознакомьтесь и соблюдайте [Кодекс поведения](./code-of-conduct.md).

## Сообщение о проблемах { #filing-issues }

Если вы обнаружите какие-либо ошибки или у вас возникнут какие-либо проблемы, выполните поиск по сообщенной проблеме, поскольку кто-то мог столкнуться с такой же проблемой, или мы активно работаем над решением.

Если вы не можете найти ничего, связанного с вашей проблемой, свяжитесь с нами, отправив сообщение о проблеме. Чтобы помочь нам диагностировать и решить проблему, предоставьте как можно больше информации, в том числе:

- Программное обеспечение: версия GPUStack, способ установки, информация об операционной системе и т. д.
- Аппаратное обеспечение: информация об узле, информация о графическом процессоре и т. д.
- Действия по воспроизведению: Предоставьте как можно больше подробностей о том, как вы попали в описанную ситуацию.
- Журналы: укажите все соответствующие журналы, например журналы сервера, журналы рабочих и т. д.

## Участие в разработке { #contributing-code }

Для настройки среды разработки см. [Руководство по разработке](./development.md).

Если вы исправляете небольшую проблему, можно сразу отправить pull request (PR). Однако, если вы планируете крупный PR с новой функцией или исправлением относительно сложной ошибки, сначала создайте issue с описанием изменений и их обоснованием. Если вы исправляете ошибку, объясните, как её воспроизвести.

## Обновление документации { #updating-documentation }

Если у вас есть какие-либо обновления нашей документации, не стесняйтесь сообщить о проблеме с меткой `documentation` или сделать запрос на включение.

Английская документация в `docs/` служит основным источником. Поддерживайте переводы на упрощённый китайский, японский, русский и турецкий языки по соответствующим путям в `docs-i18n/zh/`, `docs-i18n/ja/`, `docs-i18n/ru/` и `docs-i18n/tr/`. Изображения и другие общие ресурсы наследуются из `docs/`. Сохраняйте исходные английские идентификаторы заголовков в переведённых заголовках (например, `## 安装 { #installation }`), чтобы ссылки и переключение языков оставались согласованными.

Переведите метки навигации и темы в соответствующих файлах `docs-i18n/mkdocs/zh.yml`, `docs-i18n/mkdocs/ja.yml`, `docs-i18n/mkdocs/ru.yml` и `docs-i18n/mkdocs/tr.yml`. Сохраняйте команды, ключи конфигурации, примеры кода, ссылки и названия моделей при переводе с английского. На страницах без перевода или с `translation_status: pending` в начале отображается английский источник с примечанием.

Запустите `make build-docs`, чтобы создать все пять языков. Для предварительного просмотра всех пяти языков с автоматической перезагрузкой используйте `mkdocs serve` или `make serve-docs`; изменения переводов и языковых настроек в `docs-i18n/` автоматически пересобирают предварительный просмотр. Английский подают в `/`; на переведенных сайтах используются `/zh/`, `/ja/`, `/ru/` и `/tr/`. `bash hack/build-docs.sh --offline` создает связанный сайт в `gpustack/help/`, обслуживаемый GPUStack в `/help/` и соответствующих путях `/help/<language>/`. Каждый язык имеет свой собственный локальный поисковый индекс. Поиск по японскому языку использует токенизатор, включенный в тему документации, и работает в автономном режиме.

Обычные `mkdocs build` и `mike deploy` также создают все языки с помощью настроенных перехватчиков документации. При развертывании с использованием версий переводы хранятся в одном каталоге версий, например `/latest/ja/` или `/2.3/ja/`. Используйте существующий процесс выпуска для публикации полностью созданного сайта; сама по себе сборка не публикует документацию.
