# Влияние квантизации на производительность инференса vLLM { #the-impact-of-quantization-on-vllm-inference-performance }

Квантизация снижает вычислительные затраты и расход памяти при инференсе, представляя веса и активации типами меньшей разрядности, например 8-битными целыми (int8), вместо обычных 32-битных чисел с плавающей точкой (float32).

Цель этого документа — оценить распространённые [методы квантизации](https://docs.vllm.ai/en/latest/features/quantization/index.html) в vLLM и их влияние на производительность инференса, особенно пропускную способность при высокой конкурентности.


## Выводы { #conclusions }

1. **Квантизация весов и активаций** (например, FP8) даёт значительный прирост производительности при минимальной потере качества и рекомендуется для большинства сценариев. Статическая квантизация обеспечивает более высокую пропускную способность, чем динамическая; точность зависит от калибровочных данных:

    - **Динамическая FP8**: +14.8% TPS, -14.1% TTFT, -21.8% TPOT
    - **Статическая FP8**: +26.7% TPS, -20.4% TTFT, -32.4% TPOT

2. **Большинство методов квантизации** заметно повышают пропускную способность при ограниченной VRAM; в экспериментах наблюдался прирост до +46%.

3. **Квантизация только весов** при достаточном объёме VRAM ухудшает TPS, TTFT и TPOT из-за накладных расходов деквантизации.

4. **Среди методов квантизации только весов** лучшую производительность инференса дают AWQ и GPTQ. bitsandbytes и GGUF не рекомендуются из-за низкой производительности или проблем совместимости.

5. В экспериментах **ядра vLLM по умолчанию** для AWQ и GPTQ превосходят пользовательские реализации ядер.

6. **Квантизация KV-кэша** даёт сравнительно небольшой прирост пропускной способности по сравнению с другими методами оптимизации.

## Технические сведения { #technical-background }

### Тип квантизации { #quantization-type }

| Тип квантизации | Описание |
|-------------------|-------------|
| Только веса | После обучения квантизуются только веса; активации сохраняют полную разрядность |
| Динамическая | Веса квантизуются заранее; активации — на лету при инференсе |
| Статическая | Веса и активации квантизуются заранее после калибровки на репрезентативных данных |
| Обучение с учётом квантизации | Моделирует квантизацию при обучении, чтобы модель адаптировалась к меньшей разрядности |

### Калибровка { #calibration }

Калибровка — этап квантизации, на котором вычисляются диапазоны float32. Для весов это относительно просто, поскольку фактический диапазон известен в момент квантизации. Для активаций ситуация менее определённа, и используются разные подходы:

1. **Динамическая квантизация после обучения**: диапазон каждой активации вычисляется на лету во время выполнения. Это позволяет получить хорошие результаты без больших усилий, но из-за повторного вычисления диапазонов может быть медленнее статической квантизации. На некотором оборудовании этот вариант недоступен.

2. **Статическая квантизация после обучения**: диапазон каждой активации вычисляется заранее, на этапе квантизации; обычно через модель пропускают репрезентативные данные и записывают значения активаций. На практике выполняются следующие шаги:
   - К активациям добавляются наблюдатели для записи их значений
   - Выполняется некоторое число прямых проходов по калибровочному набору данных (достаточно примерно 200 примеров)
   - Диапазоны значений для каждого вычисления определяются выбранным методом калибровки

3. **Обучение с учётом квантизации**: диапазон каждой активации вычисляется во время обучения по той же идее, что и при статической квантизации после обучения. Но вместо наблюдателей применяются операторы «псевдоквантизации»: они записывают значения и одновременно моделируют ошибку квантизации, позволяя модели к ней адаптироваться.

### Квантизация KV-кэша { #kv-cache-quantization }

Квантизация KV-кэша уменьшает потребление памяти при инференсе, сохраняя кэш ключей и значений в формате меньшей разрядности. Это позволяет кэшировать больше токенов и повышает пропускную способность. vLLM поддерживает FP8 (E4M3 и E5M2), но не KV-кэш INT8. Исследуются также 4-битные и 2-битные варианты, однако они обычно заметно ухудшают точность, например снижают MMLU.

### Ядра квантизации { #quantization-kernels }

vLLM предлагает несколько реализаций ядер квантизации для методов AWQ и GPTQ. По умолчанию AWQ использует официальное ядро AWQ, а модели GPTQ — ExLlamaV2. Также доступны оптимизированные ядра Marlin и Machete, повышающие производительность, особенно при больших батчах.

### Снижение качества инференса { #inference-quality-degradation }

Квантизация может ухудшать качество инференса. Хотя этот документ посвящён главным образом показателям производительности, для оценки влияния на качество приведены следующие материалы:

Бенчмарки модели Qwen3-8B с разными методами квантизации:

## Условия эксперимента { #experimental-setup }

- **Модель**: Qwen3-8B
- **Оборудование**: NVIDIA RTX 4090 24GB / A100 80GB / H100 80GB
- **Версия vLLM**: v0.9.2
- **Набор данных**: ShareGPT
- **Скрипт бенчмарка**:
```bash
# Prepare the ShareGPT dataset
wget https://huggingface.co/datasets/anon8231489123/ShareGPT_Vicuna_unfiltered/resolve/main/ShareGPT_V3_unfiltered_cleaned_split.json

# Benchmark on ShareGPT dataset
vllm bench serve --model Qwen/Qwen3-8B --endpoint-type openai-chat --endpoint /v1/chat/completions --dataset-name sharegpt --dataset-path ShareGPT_V3_unfiltered_cleaned_split.json --num-prompts 1000
```
