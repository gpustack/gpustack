# Оптимизация пропускной способности GLM-4.x на NVIDIA H200 GPU { #optimizing-glm-4x-throughput-on-nvidia-h200-gpus }


## Вывод { #conclusion }

![glm-4.6-h200](../../assets/performance-lab/glm-4.6-h200.png)

Рекомендуемая конфигурация для оптимизации пропускной способности GLM-4.x (4.5, 4.6 и 4.7) на H200 GPU:

???+ tip "Команда обслуживания модели"
    ```bash
    python3 -m sglang.launch_server --model zai-org/GLM-4.6-FP8 --tp 4 --tool-call-parser glm --reasoning-parser glm45
    ```

Сравнение результатов бенчмарков до и после оптимизации:

| Сценарий бенчмарка | базовая конфигурация (vLLM без оптимизации) | После оптимизации (в пересчёте на то же число GPU) |
|----------|-------------------------------------------|-----------|
| **ShareGPT** | Общий TPS: 6030.90<br>Среднее TPOT(ms): 197.85 | Общий TPS: 7081.34x2 <span style="background-color:lightgreen;">(+134.8%)</span><br>Среднее TPOT(ms): 256.43 |
| **Короткий запрос** | Общий TPS: 9497.19<br>Среднее TPOT(ms): 351.26 | Общий TPS: 21234.81x2  <span style="background-color:lightgreen;">(+347.2%)</span><br>Среднее TPOT(ms): 800.25 |
| **Запрос средней длины** | Общий TPS: 17214.85<br>Среднее TPOT(ms): 269.75 | Общий TPS: 17363.22x2  <span style="background-color:lightgreen;">(+101.7%)</span><br>Среднее TPOT(ms): 144.82 |
| **Длинный запрос** | Общий TPS: 16714.91<br>Среднее TPOT(ms): 205.69 | Общий TPS: 14979.90x2 <span style="background-color:lightgreen;">(+79.2%)</span><br>Среднее TPOT(ms): 97.74 |
| **Очень длинный запрос** | Общий TPS: 15066.09<br>Среднее TPOT(ms): 479.17 | Общий TPS: 12223.53x2 <span style="background-color:lightgreen;">(+62.3%)</span><br>Среднее TPOT(ms): 191.61 |


!!! note
    1. Наши бенчмарки не охватывают все возможные сочетания оптимизаций. Например, отправной точкой дальнейшей настройки становится движок инференса с лучшей производительностью при настройках по умолчанию. Такое отсечение вариантов даёт локальный оптимум, который может не совпадать с глобальным.
    2. Есть и другие методы оптимизации, зависящие от сценария использования: максимальный размер батча, настройки планировщика, расширенный KV-кэш, CUDA graph и т. д. Выводы этого документа могут служить отправной точкой для более целенаправленной оптимизации.
    3. Тесты проводились на определённых аппаратных и программных конфигурациях. Развитие движков инференса может привести к новым выводам.
    4. Квантизация может влиять на точность, однако для большинства моделей FP8 обеспечивает снижение точности менее чем на 1%. Подробности см. в [результатах оценки](https://github.com/Tencent/AngelSlim/blob/main/README_en.md#-benchmark). Поэтому для обслуживания с высокой пропускной способностью настоятельно рекомендуется квантизация FP8.

Если что-то упущено или требуется обновление с учётом новых изменений, [сообщите нам](https://github.com/gpustack/gpustack/issues/new/choose).

## Цель оптимизации { #optimization-objective }

Высокая пропускная способность при высокой конкурентности запросов.

## Условия эксперимента { #experimental-setup }

### Модель { #model }

zai-org/GLM-4.6

### Оборудование { #hardware }

8 × NVIDIA H200 SXM GPU на одном узле.

### Версия движка { #engine-version }

- vLLM: v0.11.0
- SGLang: v0.5.3
- TensorRT-LLM: v1.0.0

### Набор данных бенчмарка { #benchmark-dataset }

1. ShareGPT
2. Случайный набор данных с различной длиной последовательностей:
    - Очень длинный запрос: 32000 входных токенов, 100 выходных токенов
    - Длинный запрос: 4000 входных токенов, 200 выходных токенов
    - Запрос средней длины: 2000 входных токенов, 100 выходных токенов
    - Короткий запрос: 128 входных токенов, 4 выходных токенов

### Скрипт бенчмарка { #benchmark-script }

Для оценки производительности модели используется **vLLM bench CLI**. Бенчмарк запускается следующей командой:

```bash
# Prepare the ShareGPT dataset
wget https://huggingface.co/datasets/anon8231489123/ShareGPT_Vicuna_unfiltered/resolve/main/ShareGPT_V3_unfiltered_cleaned_split.json

# Benchmark on ShareGPT dataset
vllm bench serve --model zai-org/GLM-4.6 --backend openai-chat --endpoint /v1/chat/completions --dataset-name sharegpt --dataset-path ShareGPT_V3_unfiltered_cleaned_split.json --num-prompts 1000

# Benchmark on random dataset (fixed seed for reproducibility)
vllm bench serve --model zai-org/GLM-4.6 --backend openai-chat --endpoint /v1/chat/completions --dataset-name random --random-input-len 4000 --random-output-len 200 --num-prompts 500 --seed 42
```
