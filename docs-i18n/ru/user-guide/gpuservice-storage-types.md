# Типы хранилищ сервисов графического процессора { #gpu-service-storage-types }

Типы хранилища служб графического процессора позволяют определить общие серверные хранилища файловой системы — NFS или S3 — для экземпляров службы графического процессора.

Это помогает администраторам управлять определениями хранилищ в нескольких кластерах Kubernetes. После определения тип хранилища можно выбрать при создании [Хранилище службы графического процессора](gpuservice-storage.md).

Под капотом каждый тип хранилища реализован как Kubernetes `StorageClass` в целевом кластере.

## Просмотр типов хранилищ { #browse-storage-types }

Перейдите на страницу `GPU Service` > `Storage Types`, чтобы просмотреть все типы хранилищ и их подробную информацию.

![Скриншот: список типов хранилищ](../assets/gpuservice/storage-types/list.png)

Вы можете фильтровать типы хранилищ по отображаемому имени или имени — любое значение может отображаться в столбце `Name`. Сортировка порядков столбцов `Name` по отображаемой метке.

## Добавление типа хранилища { #adding-a-storage-type }

На странице `Storage Types` нажмите `Add Storage Type`, чтобы открыть форму создания.

![Снимок экрана: форма добавления типа хранилища](../assets/gpuservice/storage-types/add.png)

Введите `Name`, при желании `Display Name`, затем выберите `Type`. Остальные поля зависят от выбранного типа.

**NFS** — смонтировать экспортированный общий ресурс с NFS-сервера:

- **NFS-сервер** (обязательно): имя хоста или IP-адрес сервера NFS.
- **Путь к общему ресурсу** (обязательно): путь к экспортированному общему ресурсу на сервере NFS.
- **Подкаталог**: подкаталог внутри общего ресурса, который будет использоваться для тома. Если оставить пустым, используется корень общего ресурса.
- **Разрешения на монтирование**: разрешения, применяемые к смонтированному каталогу, например `0777`. По умолчанию — `0`, что соответствует разрешениям, настроенным на сервере NFS.
- **Параметры монтирования**: параметры монтирования NFS, добавленные в виде отдельных записей. По умолчанию: `hard`, `vers=4`, `rsize=1048576`, `wsize=1048576`, `noatime` и `nodiratime`.

**S3** — смонтировать S3-совместимую корзину объектного хранилища:

- **Конечная точка** (обязательно): URL-адрес конечной точки хранилища, совместимого с S3.
- **Регион**: регион хранилища S3, если применимо.
- **Bucket**: имя сегмента, которое нужно использовать. Если оставить пустым, создается сегмент по умолчанию с именем `gpu-instance-pv-{id}`.
- **Ключ доступа** (обязательно): ключ доступа, используемый для аутентификации в хранилище.
- **Секретный ключ** (обязательно): секретный ключ, используемый для аутентификации в хранилище. Он доступен только для записи и никогда не возвращается в ответах API.
- **Небезопасно**: пропустить проверку сертификата TLS/SSL при подключении к конечной точке. По умолчанию отключено.
- **Параметры**: параметры монтирования базового драйвера [GeeseFS](https://github.com/yandex-cloud/geesefs), добавленные в виде отдельных записей. Значения по умолчанию соответствуют предустановке **Интенсивная запись больших файлов**, которая подходит для большинства рабочих нагрузок.

Тома S3 монтируются с помощью [GeeseFS](https://github.com/yandex-cloud/geesefs), а `Mount Options` передаются ему напрямую. Выберите предустановку, соответствующую вашему шаблону доступа, и добавьте параметры **Сервис, несовместимый с Yandex S3**, если ваша конечная точка не является хранилищем объектов Яндекса.

??? note "Общие настройки параметров монтирования GeeseFS"

    | Вариант использования | Варианты крепления |
    | --- | --- |
    | Интенсивная запись для больших файлов (по умолчанию) | `--no-checksum` `--memory-limit=4000` `--max-flushers=32` `--max-parallel-parts=32` `--part-sizes=25` |
    | Последовательное чтение больших файлов | `--read-ahead-large=200000` `--large-read-cutoff=10240` `--read-ahead-parallel=40000` `--memory-limit=8000` |
    | Случайное чтение для небольших файлов | `--read-ahead-small=64` `--small-read-cutoff=64` `--read-ahead=1024` `--stat-cache-ttl=300s` `--entry-limit=200000` |
    | Высокая доступность для записи | `--sdk-max-retries=10` `--read-retry-attempts=5` `--fsync-on-close` `--cache=/mnt/disk-cache` |
    | Сервис, не совместимый с Яндекс S3 | `--list-type=2` `--no-specials` |

После заполнения необходимых полей нажмите `Save`, чтобы создать тип хранилища.

## Редактирование типа хранилища. { #editing-a-storage-type }

После создания можно изменить только отображаемое имя.

!!! note

    В будущем выпуске запланировано дальнейшее редактирование конфигурации типа хранилища.

## Удаление типа хранилища { #deleting-a-storage-type }

Нажмите `Delete` на типе хранилища и подтвердите. После этого тип хранилища будет удален из списка.

!!! warning

    Прежде чем удалять тип хранилища, сначала удалите любое [Хранилище службы графического процессора](gpuservice-storage.md), созданное на его основе.
