# Сервисное хранилище графического процессора { #gpu-service-storage }

На основе [Типы хранилища служб графического процессора](gpuservice-storage-types.md) хранилище служб графического процессора позволяет выделить постоянное хранилище и подключить его к нескольким экземплярам службы графического процессора.

Это полезно для данных, моделей и других файлов, которые необходимо использовать совместно между экземплярами.

GPUStack управляет несколькими кластерами Kubernetes и предоставляет унифицированный интерфейс для совместного использования хранилища сервисов графических процессоров между ними.

Под капотом каждый элемент хранилища реализован как Kubernetes `PersistentVolumeClaim` в целевом кластере.

## Просмотр хранилища { #browse-storage }

Перейдите на страницу `GPU Service` > `Storage`, чтобы просмотреть все хранилища и их сведения.

![Скриншот: Список хранилищ](../assets/gpuservice/storage/list.png)

Вы можете фильтровать хранилище по отображаемому имени или имени — любое значение может отображаться в столбце `Name`. Сортировка порядков столбцов `Name` по отображаемой метке.

## Добавление хранилища { #adding-storage }

На странице `Storage` нажмите `Add Storage`, чтобы открыть форму создания.

![Скриншот: форма добавления хранилища](../assets/gpuservice/storage/add.png)

Введите `Name`, выберите `Storage Type` (определено на странице [Типы хранения службы графического процессора](gpuservice-storage-types.md)) и установите `Capacity (GB)`. Затем нажмите `Save`.

## Редактирование хранилища { #editing-storage }

После создания можно изменить только отображаемое имя.

!!! note

    В будущем выпуске запланировано дальнейшее редактирование конфигурации хранилища.

## Удаление хранилища { #deleting-storage }

Нажмите `Delete` на элементе хранилища и подтвердите. После этого хранилище будет удалено из списка.

!!! warning

    Если хранилище все еще подключено к экземпляру службы графического процессора, его сторона кластера `PersistentVolumeClaim` не удаляется сразу. Поскольку удаление соответствует политике отсрочки, `PersistentVolumeClaim` сохраняется до тех пор, пока связанный экземпляр не будет удален, и только после этого он очищается.
