# 使用量 { #usage }

**Usage** ページは、LLM トークン、GPU/CPU インスタンスの稼働時間、ストレージ容量など、GPUStack のリソースが時間とともにどのように消費されたかを表示します。利用の広がりを追跡し、消費をユーザーに帰属させ、コストを検討できます。

## Usage ページへのアクセス { #accessing-the-usage-page }

1. 左側のナビゲーションから、棒グラフアイコンの `Usage` ページに移動します。
2. `Summary`、`Tokens`、`GPU Instances`、`Storage`、`Resource Events` のいずれかのタブを選択します。
3. `date range` と必要なフィルターを設定して、レポートの範囲を指定します。

各タブの内容：

- **概要** — トークン、演算、ストレージをひと目で確認できます。
- **トークン** — モデル、ユーザー、API キー別の LLM トークン消費量。
- **GPU インスタンス** — インスタンスタイプ、インスタンス、ユーザー別の GPU/CPU インスタンスの稼働時間。
- **ストレージ** — ストレージ、ユーザー別のストレージ容量使用量。
- **リソースイベント** — 演算とストレージの数値の根拠となるライフサイクル監査ログ。

## 計測対象 { #what-gets-metered }

| リソース | 計測される期間 | 集計単位 |
| --- | --- | --- |
| トークン | ゲートウェイを通じて推論リクエストが処理される間。 | 日単位 |
| GPU/CPU インスタンス | インスタンスが実行中（計測対象）のフェーズにある間。**停止済み**または削除済みのインスタンスは加算されません。 | 時間単位 |
| ストレージ | 作成から削除まで。接続の有無にかかわらず容量を計測します。 | 時間単位 |

## 表示範囲 { #visibility }

GPUStack には、**管理者**と**ユーザー**の 2 つのロールがあります（[ユーザー管理](user-management.md)を参照）。

- **管理者** — 全ユーザーの使用量を閲覧でき、**ユーザーで絞り込み**コントロールで範囲を限定できます。
- **ユーザー** — 自分の使用量だけを閲覧できます。ユーザー別の内訳は利用できません。

## 共通の操作 { #common-controls }

独自のフィルターを持つ Resource Events を除き、各タブは共通の操作を使用します。

- **日付範囲** — レポートの対象期間。既定は過去 30 日です。
- **ユーザーで絞り込み** — 特定のユーザーに限定します（管理者のみ）。Tokens タブには、さらに**モデルで絞り込み**と **API キーで絞り込み**があります。
- **更新** — 現在のフィルターで再取得します。
- **メトリクス** — トレンドグラフと KPI の並べ替えに使う値（GPU 時間、インスタンス時間など）。
- **グループ化** — グループごと（インスタンスタイプごとなど）の系列にトレンドグラフを分割します。
- **粒度** — トレンドの集計単位。GPU Instances と Storage は、**時間 / 日 / 週 / 月**に対応します。Tokens は**日 / 週 / 月**だけに対応します（トークン使用量は日次集計なので、時間単位の集計はありません）。
- **エクスポート**（Tokens / GPU Instances / Storage で利用できるダウンロードアイコン）— 現在のフィルターを適用した内訳のプレビューを開き、ダウンロードできます。

## メトリクスの定義 { #metric-definitions }

| メトリクス | 意味 |
| --- | --- |
| **入力トークン** | プロンプトトークン。**キャッシュ済み入力トークン**は、そのうちプロンプトキャッシュから提供された部分です。 |
| **出力トークン** | 生成した補完トークン。 |
| **合計トークン** | 入力 + 出力。 |
| **インスタンス時間** | インスタンスの実時間の合計：Σ(稼働時間)。インスタンスが保持するカード数には依存しません。 |
| **GPU 時間** | アクセラレーターの稼働時間：Σ(稼働時間 × GPU カード数)。2 GPU のインスタンスを 1 時間実行すると、GPU 時間は 2、インスタンス時間は 1 です。 |
| **GB 日** | 時間を考慮した確保済みストレージ：容量（GB）× 保持日数。 |
| **GB 時間** | GB 日と同じ量を時間単位で表したもの。 |
| **アクティブなインスタンス / ストレージ / ユーザー** | 対象期間内に存続している（**削除済み**でない）リソース。 |
| **最終利用** | そのリソースで使用量が発生した、最も新しい集計期間。 |

!!! note

    削除したリソースの過去の使用量は保持されます。削除したモデル、インスタンス、ストレージも、**削除済み**の表示付きで表に残り、合計に含まれますが、**アクティブ**とは数えられなくなります。

## 概要 { #summary }

![使用量の概要](../assets/usage/usage-summary.png)

Summary タブには、**トークン**、**演算**、**ストレージ**の 3 つのセクションがあります。それぞれ、主要な統計値、種類別のドーナツグラフ、選択期間のトレンドグラフを表示するため、タブを切り替えずに 3 種類のリソースをすばやく確認できます。

## トークン { #tokens }

![トークン使用量](../assets/usage/usage-tokens.png)

LLM 推論のトークン消費量です。上部の KPI は、**入力 / 出力 / 合計トークン**、**API リクエスト**、**使用モデル数**です。

下部では、詳細表を 3 つの方法でグループ化します。

- **モデル** — モデルごとの、入力トークン、キャッシュ済み入力トークン、出力トークン、合計トークン、API リクエスト、最終利用。
- **ユーザー** — ユーザーごと（管理者のみ）。
- **API キー** — API キーごと。

## GPU インスタンス { #gpu-instances }

![GPU インスタンス使用量](../assets/usage/usage-gpu-instances.png)

GPU と CPU のインスタンス稼働時間です。KPI は、**GPU 時間**、**インスタンス時間**、**アクティブなインスタンス数**、**アクティブユーザー数**です。グラフのメトリクスに **GPU 時間**または**インスタンス時間**を選び、**インスタンスタイプ**、**インスタンス**、**ユーザー**でトレンドをグループ化します。

詳細表のグループ：

- **インスタンスタイプ** — タイプごとの、GPU 時間、インスタンス時間、アクティブなインスタンス数、最終利用。
- **インスタンス** — 個々のインスタンス。
- **ユーザー** — ユーザーごと（管理者のみ）。

!!! note

    CPU インスタンスにはアクセラレーターがないため、**インスタンス時間**には加算されますが、**GPU 時間**には加算されません。

## ストレージ { #storage }

![ストレージ使用量](../assets/usage/usage-storage.png)

ストレージ容量の使用量です。KPI は、**GB 日**、**GB 時間**、**アクティブなストレージ数**、**アクティブユーザー数**です。グラフのメトリクスに **GB 日**または **GB 時間**を選択し、**ストレージ**または**ユーザー**でグループ化します。

詳細表のグループ：

- **ストレージ** — ボリュームごとの、種類、容量、GB 日、GB 時間、最終利用。
- **ユーザー** — ユーザーごと（管理者のみ）。

!!! note

    ストレージは接続の有無にかかわらず作成から削除まで計測されるため、存在するだけで使用していなくても、GB 日 / GB 時間は加算されます。

## リソースイベント { #resource-events }

![リソースイベントの使用量](../assets/usage/usage-resource-events.png)

演算とストレージの数値の根拠となるライフサイクル監査ログです。計測に関係する状態遷移ごとに 1 行を記録し、数値の理由を調べる際に役立ちます。

フィルターは、**日付範囲**、**リソースの種類**（GPU Instance / Storage）、**イベントの種類**、**リソース名**のあいまい検索です。

## タイムゾーン { #timezone }

Usage ページのすべての日付と時刻（トレンドの集計期間、**最終利用**、リソースイベントの時刻）は、設定可能な単一の**集計タイムゾーン**で表示されます。これにより、すべてのタブが同じ暦の境界にそろいます。Server の環境変数 `GPUSTACK_TIMEZONE` で制御します（従来の `GPUSTACK_USAGE_ROLLUP_TIMEZONE` も非推奨の別名として機能します）。既定値は Server の OS のローカルタイムゾーンです。夏時間の注意を含む詳細は、[環境変数](../environment-variables.md#usage-tracking-configuration)を参照してください。

## データの保持 { #data-retention }

トークン、演算、ストレージの集計は約 13 か月保持され、その後、バックグラウンドジョブによってアーカイブ表に移されます。保持期間とアーカイブのスケジュールは、環境変数 `GPUSTACK_*_RETENTION_MONTHS` と `GPUSTACK_*_ARCHIVE_CRON` で設定できます。
