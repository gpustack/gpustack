# GPUStack への貢献 { #contributing-to-gpustack }

GPUStack への貢献に時間を割いていただき、ありがとうございます。

[行動規範](./code-of-conduct.md)を確認し、遵守してください。

## Issue の報告 { #filing-issues }

不具合や問題が見つかった場合は、まず既存の Issue を検索してください。同じ問題の報告や、対応中の解決策があるかもしれません。

関連する Issue がない場合は、新しい Issue を作成してください。診断と解決に役立つよう、次の情報をできるだけ詳しく記載してください。

- ソフトウェア：GPUStack のバージョン、インストール方法、OS 情報など。
- ハードウェア：ノード情報、GPU 情報など。
- 再現手順：報告した状況に至るまでの操作をできるだけ詳しく記載してください。
- ログ：サーバーログ、ワーカーログなど、関連するログを添付してください。

## コードの貢献 { #contributing-code }

開発環境のセットアップは、[開発ガイド](./development.md)をご覧ください。

小さな問題の修正は、そのまま PR を提出できます。新機能や比較的複雑な不具合修正など、大きな PR を予定している場合は、変更内容と動機を説明する Issue を先に作成してください。不具合の場合は、再現方法も説明してください。

## ドキュメントの更新 { #updating-documentation }

ドキュメントを更新する場合は、`documentation` ラベル付きの Issue またはプルリクエストを作成してください。

正本となる英語ドキュメントは `docs/` にあります。簡体字中国語、日本語、ロシア語、トルコ語の翻訳は、`docs-i18n/zh/`、`docs-i18n/ja/`、`docs-i18n/ru/`、`docs-i18n/tr/` の同じ相対パスに追加します。画像などの共有アセットは `docs/` から継承します。翻訳した見出しには英語の見出し ID を保持し（例：`## インストール { #installation }`）、リンクや言語切り替えの整合性を保ちます。

ナビゲーションとテーマのラベルは、対応する `docs-i18n/mkdocs/zh.yml`、`docs-i18n/mkdocs/ja.yml`、`docs-i18n/mkdocs/ru.yml`、`docs-i18n/mkdocs/tr.yml` で翻訳します。英語から翻訳する際は、コマンド、設定キー、コード例、リンク、モデル名を保持してください。翻訳がないページ、またはフロントマターに `translation_status: pending` があるページは、通知とともに英語の原文を表示します。

`make build-docs` で全5言語をビルドします。`mkdocs serve` または `make serve-docs` で全5言語のライブリロード付きプレビューを起動できます。`docs-i18n/` 内の翻訳や言語設定を変更すると、プレビューが自動的に再ビルドされます。英語は `/`、翻訳は `/zh/`、`/ja/`、`/ru/`、`/tr/` です。
`bash hack/build-docs.sh --offline` は内蔵サイトを `gpustack/help/` に構築します。GPUStack は `/help/` と各 `/help/<language>/` で配信します。各言語に独立したローカル検索インデックスがあります。日本語検索はテーマに同梱されたトークナイザーを使用し、オフラインで動作します。

通常の `mkdocs build` と `mike deploy` も、設定されたドキュメントフックで
すべての言語をビルドします。バージョン付きデプロイでは、翻訳は
`/latest/ja/` や `/2.3/ja/` のように同じバージョンディレクトリに含まれます。生成された
サイト全体を公開するには、既存のリリース手順を使用してください。ビルドだけでは
ドキュメントは公開されません。
