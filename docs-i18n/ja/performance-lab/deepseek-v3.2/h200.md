# NVIDIA H200 GPU 上での DeepSeek-V3.2 のスループット最適化 { #optimizing-deepseek-v32-throughput-on-nvidia-h200-gpus }

## 結論 { #conclusion }

![DeepSeek-V3.2 H200 スループットの最適化](../../assets/performance-lab/deepseek-v3.2-h200.png)
単一ノードの H200x8 上で DeepSeek-V3.2 のスループットを最適化するための推奨設定：

???+ tip "推論サービスのコマンド"
    ```bash
    python3 -m sglang.launch_server --model deepseek-ai/DeepSeek-V3.2 \
    --chat-template ./tool_chat_template_deepseekv32.jinja \
    --tp-size 8 --dp-size 8 --enable-dp-attention \
    --reasoning-parser deepseek-v3 \
    --tool-call-parser deepseekv32
    ```

[tool_chat_template_deepseekv32.jinja](https://github.com/sgl-project/sglang/blob/main/examples/chat_template/tool_chat_template_deepseekv32.jinja) へのリンク。 

以下のベンチマークに基づき、**8×H200** 上での **DeepSeek-V3.2** のスループット最適化には、上記の設定を推奨します。

**並列化**と**ツール呼び出し設定**の性能改善が最も大きいため、推奨コマンドに含めています。**コンテキスト長の調整**によってスループットをさらに高められますが、ワークロードへの依存が大きいため、実際の利用状況に応じて調整してください。
**アテンションバックエンド**の最適化には効果がありますが、改善幅が比較的小さく、データセットによっても変わる可能性があるため、デフォルトの推奨設定には含めていません。

最適化前後のベンチマーク結果の比較：

| ベンチマークケース | 基準設定（最適化なしの vLLM） | 最適化後 |
|---------------|--------------------------------------------|-----------|
| **ShareGPT** | 合計 TPS: 5713.95<br>平均 TPOT(ms): 275.03 | 合計 TPS: 8968.32 <span style="background-color:lightgreen;">(+56.95%)</span><br>平均 TPOT(ms): 203.05 |
| **短いプロンプト** | 合計 TPS: 10071.49<br>平均 TPOT(ms): 781.80 | 合計 TPS: 18227.38 <span style="background-color:lightgreen;">(+80.98%)</span><br>平均 TPOT(ms): 776.55 |
| **中程度のプロンプト** | 合計 TPS: 10925.59<br>平均 TPOT(ms): 354.59 | 合計 TPS: 27712.54 <span style="background-color:lightgreen;">(+153.65%)</span><br>平均 TPOT(ms): 192.24 |
| **長いプロンプト** | 合計 TPS: 9974.26<br>平均 TPOT(ms): 226.74 | 合計 TPS: 20545.67 <span style="background-color:lightgreen;">(+105.99%)</span><br>平均 TPOT(ms): 177.95 |
| **非常に長いプロンプト** | 合計 TPS: 9709.27<br>平均 TPOT(ms): 472.52 | 合計 TPS: 20045.18 <span style="background-color:lightgreen;">(+106.45%)</span><br>平均 TPOT(ms): 246.26 |

!!! note
    1. 本ベンチマークは、考えられるすべての最適化の組み合わせを網羅していません。たとえば、デフォルト設定で最も性能が高い推論エンジンを選び、それを追加調整の出発点としています。このような候補の絞り込みで得られるのは局所最適解であり、大域最適解とは限りません。
    2. 最大バッチサイズ、スケジューリング設定、拡張 KV キャッシュ、CUDA graph など、利用シナリオに応じた最適化もあります。本書の結論は、用途に合わせてさらに最適化するための出発点として利用できます。
    3. 本テストは特定のハードウェアとソフトウェアの構成で実施しています。推論エンジンの進化により、結論が変わる可能性があります。

記載漏れや最新の変更を反映すべき点があれば、[お知らせください](https://github.com/gpustack/gpustack/issues/new/choose)。


## 最適化の目標 { #optimization-objective }

高並列度のリクエストで高スループットを実現します。

## 実験環境 { #experimental-setup }

### モデル { #model }

deepseek-ai/DeepSeek-V3.2

### ハードウェア { #hardware }

単一ノードに 8 × NVIDIA H200 SXM GPU。

### エンジンのバージョン { #engine-version }

- vLLM: v0.13.0
- SGLang: v0.5.6.post2
- TensorRT-LLM: 1.2.0rc5

### ベンチマークデータセット { #benchmark-dataset }

1. ShareGPT
2. シーケンス長を変えたランダムデータセット：
    - 非常に長いプロンプト： 32000 入力トークン, 100 出力トークン
    - 長いプロンプト： 4000 入力トークン, 200 出力トークン
    - 中程度のプロンプト： 2000 入力トークン, 100 出力トークン
    - 短いプロンプト： 128 入力トークン, 4 出力トークン
    - 生成の多いプロンプト： 1K 入力トークン, 2K 出力トークン

### ベンチマークスクリプト { #benchmark-script }

モデルの性能評価には **vLLM bench CLI** ツールを使用します。ベンチマークを実行するコマンドは次のとおりです：

```bash
# Prepare the ShareGPT dataset
wget https://huggingface.co/datasets/anon8231489123/ShareGPT_Vicuna_unfiltered/resolve/main/ShareGPT_V3_unfiltered_cleaned_split.json

# Benchmark on ShareGPT dataset
vllm bench serve --model deepseek-ai/DeepSeek-V3.2 --backend openai-chat --endpoint /v1/chat/completions --dataset-name sharegpt --dataset-path ShareGPT_V3_unfiltered_cleaned_split.json --num-prompts 1000

# Benchmark on random dataset (fixed seed for reproducibility)
vllm bench serve --model deepseek-ai/DeepSeek-V3.2 --backend openai-chat --endpoint /v1/chat/completions --dataset-name random --random-input-len 4000 --random-output-len 200 --num-prompts 500 --seed 42
```

#### 並列化: DCP { #parallelism-dcp }

??? info "推論サービスのスクリプト"
    ```bash
    vllm serve deepseek-ai/DeepSeek-V3.2 -tp 8 --tokenizer-mode deepseek_v32 --reasoning-parser deepseek_v3 \
    -dcp 8
    ```

DeepSeek V3.2 は FlashMLA の疎なアテンションバックエンドを使用しますが、現在、このバックエンドはデコード時に softmax の log-sum-exp（LSE）を公開しません。Decode Context Parallelism（DCP）では、ランク間で正しく集約するために softmax LSE が必要です。そのため、現時点で FlashMLA は DCP に対応しておらず、vLLM で実行時エラーが発生します。この制約は vLLM リポジトリでも議論されています（issue [#27544](https://github.com/vllm-project/vllm/issues/27544) を参照）。
