# H200 上での GLM-5.2 のスループット最適化 { #optimizing-glm-52-throughput-on-h200 }

## 結論 { #conclusion }

![スループット最適化の結果](../../assets/performance-lab/glm-5.2-h200.png)

NVIDIA H200x8 上で zai-org/GLM-5.2-FP8 のスループットを最適化するための推奨設定：

???+ tip "推論サービスのコマンド"
    ```bash
    python3 -m sglang.launch_server \
        --model-path zai-org/GLM-5.2-FP8 \
        --tp-size=8 \
        --dp-size=8 \
        --enable-dp-attention \
        --mem-fraction-static=0.85 \
        --moe-a2a-backend=deepep \
        --max-running-requests=256 \
        --kv-cache-dtype=fp8_e4m3
    ```

最適化前後のベンチマーク結果の比較：

| ベンチマークケース | 基準設定（最適化なしの vLLM） | 最適化後 |
|----------|-------------------------------------------|-----------|
| **Balanced：入力 8K / 出力 1K（最適化対象）** | 合計 TPS: 5481.90<br>平均 TPOT(ms): 636.24 | 合計 TPS: 17525.76 <span style="background-color:lightgreen;">(+219.70%)</span><br>平均 TPOT(ms): 217.89 |
| **短コンテキスト（入力 1K / 出力 128）** | 合計 TPS: 13196.90<br>平均 TPOT(ms): 316.73 | 合計 TPS: 18276.60 <span style="background-color:lightgreen;">(+38.49%)</span><br>平均 TPOT(ms): 211.06 |
| **長コンテキスト（入力 32K / 出力 100）** | 合計 TPS: 10513.68<br>平均 TPOT(ms): 1320.02 | 合計 TPS: 26433.15 <span style="background-color:lightgreen;">(+151.42%)</span><br>平均 TPOT(ms): 537.26 |
| **生成の多いワークロード（入力 1K / 出力 2K）** | 合計 TPS: 2268.18<br>平均 TPOT(ms): 42.11 | 合計 TPS: 2267.33 <span style="background-color:#ffd6d6;">(-0.04%)</span><br>平均 TPOT(ms): 46.54 |
| **ShareGPT** | 合計 TPS: 6040.94<br>平均 TPOT(ms): 149.24 | 合計 TPS: 2845.48 <span style="background-color:#ffd6d6;">(-52.90%)</span><br>平均 TPOT(ms): 331.21 |

!!! note
    1. 本ベンチマークは、考えられるすべての最適化の組み合わせを網羅していません。たとえば、デフォルト設定で最も性能が高い推論エンジンを選び、それを追加調整の出発点としています。このような候補の絞り込みで得られるのは局所最適解であり、大域最適解とは限りません。
    2. 最大バッチサイズ、スケジューリング設定、拡張 KV キャッシュ、CUDA graph など、利用シナリオに応じた最適化もあります。本書の結論は、用途に合わせてさらに最適化するための出発点として利用できます。
    3. 本テストは特定のハードウェアとソフトウェアの構成で実施しています。推論エンジンの進化により、結論が変わる可能性があります。
    4. 量子化は精度に影響する場合がありますが、多くのモデルでは FP8 量子化による精度低下は 1% 未満です。詳細は[評価結果](https://github.com/Tencent/AngelSlim/blob/main/README_en.md#-benchmark)を参照してください。そのため、低レイテンシーでのモデル提供には FP8 量子化を強く推奨します。
    5. 推奨設定は、高並列度で中～長程度の入力を処理する基準ワークロード（入力 8K / 出力 1K）に合わせて調整しています。ShareGPT のような入出力の短い対話ワークロードでは、通常のテンソル並列より性能が低下します。DP-attention と DeepEP の最適化は長いシーケンスを対象としており、短いリクエストではそのオーバーヘッドを相殺できないためです（「その他のベンチマークケース」の ShareGPT を参照）。このトレードオフは GLM-5.2 の想定用途に適しています。優れたコーディング能力を生かすコーディングエージェントではコンテキストが主に長く、この設定が最適化している領域と一致します。

記載漏れや最新の変更を反映すべき点があれば、[お知らせください](https://github.com/gpustack/gpustack/issues/new/choose)。

### ベンチマーク手法 { #benchmark-method }

本プロジェクトでは、推論ワークロードに GPUStack のワンクリックベンチマーク機能を使用します。本書のベンチマークテストも、この手順で実行しました。

GPUStack のベンチマークは [guidellm](https://github.com/vllm-project/guidellm) を基盤とし、ラッパープロジェクト [benchmark-runner](https://github.com/gpustack/benchmark-runner) を介して実装されています。

以下に示すベンチマーク構成について、GPUStack がモデルのデプロイ、ベンチマークジョブの送信、結果の収集を処理します。
