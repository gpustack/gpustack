# H200 üzerinde GLM-5.2 işlem hacmi optimizasyonu { #optimizing-glm-52-throughput-on-h200 }

## Sonuç { #conclusion }

![İşlem hacmi optimizasyonu sonucu](../../assets/performance-lab/glm-5.2-h200.png)

NVIDIA H200x8 üzerinde zai-org/GLM-5.2-FP8 işlem hacmini optimize etmek için önerilen yapılandırma:

???+ tip "Model sunum komutu"
    ```bash
    python3 -m sglang.launch_server \
        --model-path zai-org/GLM-5.2-FP8 \
        --tp-size=8 \
        --dp-size=8 \
        --enable-dp-attention \
        --mem-fraction-static=0.85 \
        --moe-a2a-backend=deepep \
        --max-running-requests=256 \
        --kv-cache-dtype=fp8_e4m3
    ```

Optimizasyon öncesi ve sonrası benchmark sonuçlarının karşılaştırması:

| Benchmark senaryosu | temel yapılandırma (optimizasyonsuz vLLM) | Optimize edilmiş |
|----------|-------------------------------------------|-----------|
| **Balanced: 8K giriş / 1K çıkış (optimizasyon hedefi)** | Toplam TPS: 5481.90<br>Ortalama TPOT(ms): 636.24 | Toplam TPS: 17525.76 <span style="background-color:lightgreen;">(+219.70%)</span><br>Ortalama TPOT(ms): 217.89 |
| **Kısa bağlam (1K giriş / 128 çıkış)** | Toplam TPS: 13196.90<br>Ortalama TPOT(ms): 316.73 | Toplam TPS: 18276.60 <span style="background-color:lightgreen;">(+38.49%)</span><br>Ortalama TPOT(ms): 211.06 |
| **Uzun bağlam (32K giriş / 100 çıkış)** | Toplam TPS: 10513.68<br>Ortalama TPOT(ms): 1320.02 | Toplam TPS: 26433.15 <span style="background-color:lightgreen;">(+151.42%)</span><br>Ortalama TPOT(ms): 537.26 |
| **Yoğun üretim (1K giriş / 2K çıkış)** | Toplam TPS: 2268.18<br>Ortalama TPOT(ms): 42.11 | Toplam TPS: 2267.33 <span style="background-color:#ffd6d6;">(-0.04%)</span><br>Ortalama TPOT(ms): 46.54 |
| **ShareGPT** | Toplam TPS: 6040.94<br>Ortalama TPOT(ms): 149.24 | Toplam TPS: 2845.48 <span style="background-color:#ffd6d6;">(-52.90%)</span><br>Ortalama TPOT(ms): 331.21 |

!!! note
    1. Benchmark testlerimiz olası tüm optimizasyon birleşimlerini kapsamaz. Örneğin, varsayılan yapılandırmasında en iyi performansı gösteren çıkarım motorunu sonraki ayarlamalar için başlangıç noktası olarak seçeriz. Bu eleme yaklaşımı yerel bir optimum verir; bu, genel optimum olmayabilir.
    2. En büyük toplu iş boyutu, zamanlama yapılandırması, genişletilmiş KV önbelleği, CUDA graph gibi belirli kullanım senaryolarına bağlı başka optimizasyonlar da vardır. Bu belgedeki sonuçlar, daha hedefli optimizasyonlar için başlangıç noktası olabilir.
    3. Testler belirli donanım ve yazılım yapılandırmalarında yürütülmüştür. Çıkarım motorlarındaki gelişmeler sonuçları değiştirebilir.
    4. Nicemleme doğruluğu etkileyebilir; ancak FP8 nicemleme çoğu modelde %1'den az doğruluk kaybı sağlayabilir. Ayrıntılar için [değerlendirme sonuçlarına](https://github.com/Tencent/AngelSlim/blob/main/README_en.md#-benchmark) bakın. Bu nedenle düşük gecikmeli sunum senaryolarında FP8 nicemleme önemle önerilir.
    5. Önerilen yapılandırma yüksek eş zamanlılık ve orta-uzun girdiler için ayarlanmıştır (temel iş yükü: 8K giriş / 1K çıkış). ShareGPT gibi kısa giriş/çıkışlı konuşma iş yüklerinde düz tensör paralelliğinden daha düşük performans verir; çünkü DP-attention ve DeepEP uzun diziler için tasarlanmıştır ve ek yükleri kısa isteklerde karşılanamaz (Diğer Benchmark Senaryoları altındaki ShareGPT'ye bakın). Bu denge GLM-5.2'nin hedef kullanımına uygundur: güçlü kodlama yeteneği, bağlamın çoğunlukla uzun olduğu kodlama ajanı sunumunu başlıca senaryo yapar; yapılandırma tam olarak bu alana göre optimize edilmiştir.

Eksik noktalar veya yeni değişiklikleri yansıtacak güncellemeler varsa [bize bildirin](https://github.com/gpustack/gpustack/issues/new/choose).
