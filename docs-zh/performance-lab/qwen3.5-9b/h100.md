# Qwen3.5-9B 吞吐量优化 { #optimizing-qwen35-9b-throughput }

## 结论 { #conclusion }

![吞吐量优化结果](../../assets/performance-lab/qwen3.5-9b-h100.png)

Qwen/Qwen3.5-9B 在 NVIDIA H100 80GB HBM3 上的吞吐量优化推荐配置：

???+ tip "推理服务命令"
    ```bash
    vllm serve Qwen/Qwen3.5-9B \
        --reasoning-parser=qwen3 \
        --performance-mode=throughput \
        --max-model-len=32768 \
        --max-num-seqs=512
    ```

优化前后的基准测试结果对比：

| 基准测试用例 | 基准配置（未做任何优化的 vLLM） | 优化后 |
|----------|-------------------------------------------|-----------|
| **ShareGPT 测试配置** | Total TPS: 11527.14<br>Mean TPOT(ms): 15.12 | Total TPS: 11768.22 <span style="background-color:lightgreen;">(+2.09%)</span><br>Mean TPOT(ms): 15.85 |
| **吞吐量测试配置** | Total TPS: 29822.16<br>Mean TPOT(ms): 34.63 | Total TPS: 34470.14 <span style="background-color:lightgreen;">(+15.59%)</span><br>Mean TPOT(ms): 36.97 |
| **长上下文测试配置** | Total TPS: 32416.84<br>Mean TPOT(ms): 10.21 | Total TPS: 32658.73 <span style="background-color:lightgreen;">(+0.75%)</span><br>Mean TPOT(ms): 9.97 |
| **生成密集型测试配置** | Total TPS: 2973.42<br>Mean TPOT(ms): 0.33 | Total TPS: 3025.11 <span style="background-color:lightgreen;">(+1.74%)</span><br>Mean TPOT(ms): 0.12 |

!!! note
    1. 基准测试未覆盖所有可能的优化组合。例如，我们会选择默认配置下表现最好的推理引擎作为后续调优的起点。这种剪枝方式得到的是局部最优解，未必是全局最优解。
    2. 其他优化方法取决于具体使用场景，包括最大批大小、调度配置、扩展 KV cache、CUDA graph 等。本文结论可作为进一步针对性优化的起点。
    3. 测试基于特定的硬件和软件环境。推理引擎的改进可能带来新的结论。
    4. 量化可能影响准确率，但对于大多数模型，FP8 量化的准确率下降可控制在 1% 以内。详情参见[评估结果](https://github.com/Tencent/AngelSlim/blob/main/README_en.md#-benchmark)。因此，强烈建议在低延迟推理服务场景中使用 FP8 量化。
    5. 推测解码能够显著降低低并发请求的延迟，但加速效果取决于基准测试数据集的数据分布和草稿模型的选择。例如，本测试所选的草稿模型使用英文数据训练，在其他语言上的表现可能不够理想。

如有遗漏或需要根据最新变化更新的内容，请[告诉我们](https://github.com/gpustack/gpustack/issues/new/choose)。

### 基准测试方法 { #benchmark-method }

本项目使用 GPUStack 的一键基准测试功能评估推理服务工作负载。本文中的基准测试均通过该流程执行。

GPUStack 的基准测试通过封装项目 [benchmark-runner](https://github.com/gpustack/benchmark-runner)，基于 [guidellm](https://github.com/vllm-project/guidellm) 实现。

对于以下基准测试配置，GPUStack 负责模型部署、基准测试任务提交和结果收集。
